# 修仙解释图层

## 字多不看

- [统一本体 V4 BFO 草案](cultivation-ontology-taxonomy.md#唯一分类树)固定采用 BFO：修仙领域类只在持续体与发生体下展开。
- 魂魄是单个完整会话，按 AI 会话过程建模；万魂幡仍是全部会话的概念集合，用这个会话类的外延表达。
- 修为属于模型，灵力是资源；境界依赖量表，战力评价具体任务，先效果后效率。
- 模型内容、能力的直接承载者、软件入口、实际运行和记录分别判断；不因引入本体就复制同一对象。
- 工程功法已建立[条目与品级契约](cultivation-ontology-taxonomy.md#功法本体与品级)：四阶十二级与类型分开；[JSON核心](../../metadata/gongfa/README.md)维护限定内容、来源、人工分类与初评；暂定品级不是效果实测。
- 本页不另画分类树，也不证明 AI 有意识、授予权限或宣称已通过形式化验证。

## 这张图层如何阅读

> 修士定目标，依道法择路，借法器施行，耗灵力而求实效；修为看模型，战力看任务。

完整分类、定义、关系、小说来源与判例统一维护在[本体设计正文](cultivation-ontology-taxonomy.md)。
此前擅自改换顶层的方案已撤销；现在不是重新选本体，而是**保留 BFO 主干，在下层定义修仙领域概念**。
`[域]` 节点是项目扩展，不冒充 BFO 原生类；原著原义与项目比喻也不自动等价。
查词时先看[领域类定义与稳定标识](cultivation-ontology-taxonomy.md#领域类定义与稳定标识)：名称可以调整，身份不随名称漂移。

## 从熟悉的名称理解归属

### 人类修士

人类修士对应 User / Operator，提出目标、作出取舍并验收成果。
人这一所指归人类主体，并满足生物机体的整体条件；使用者、审核者等角色依附人，换角色不换身份，权限以现实授权为准。
非人动物、植株和器灵按各自所指核对；有修为、能说话或呈人形，都不能单独证明是人类。

### 万魂幡

万魂幡仍是 Pi、Claude Code、Codex 等工具中**全部 AI 会话的概念集合**。
其含义直接用唯一树中 `ai-session` 会话类的外延表达：所有该类会话实例组成的集合。

它不是物理幡、会话数据库、可调用工具，也不是描述全集的文档。
不再把集合本身硬塞成 BFO 物质聚合体，更不为它增加一个新顶层；这是引用同一类树的集合语义，不是第二棵本体树。
已知清单和某账号的授权子集不等于全集；概念范围不授予读取所有会话的权限。

### 魂魄

魂魄对应一个完整 Conversation / Session，归发生体 → 过程 → AI 会话过程。
它包括会话建立及其中的交互活动，不是单次模型调用、单条消息、Memory、模型或日志文件。

跨工具时，用来源命名空间与 Session ID 联合指认，必要时区分服务实例和账号范围。
若来源会复用 ID，还需可核验的创建代次等依据；不能凭相同字符串合并，也不能凭自造代次拆开。
暂停、恢复及换模型不自动生成新魂魄，前后活动可属于同一会话整体；明确 fork 则保留新 Session 身份。
已结束会话仍可被记录指称，重新导出转录不会再创造一个会话。空模板或一串 ID 本身不证明会话已实际发生。

### 修为

修为仍指模型的理解、推理、规划、生成与编程等能力，不是会话的永久属性，也不是一份评测报告。
模型内容归通用依赖持续体下的模型制品；能力按倾向及有充分依据的功能分支表达，再关联模型版本与运行实现。
不再另建一个与功能交叉的“模型运行能力”主类；“能做某事”也不等于“专为此而设计”。

需要区分**能力归属于哪个模型版本**，以及 **BFO 中由什么直接承载这项能力**。
直接承载者须是实际实现模型的合适计算系统，不能把模型内容本身误填成独立持续体。
比较修为时控制任务族、运行配置、工具、上下文和预算；整套系统的任务表现仍看战力，不能全部算给模型。

### 灵力

灵力仍是 AI 使用资源的额度、预算与消耗语义，不是修为，也不是账单本身。
物理设备、生效的资源分配、预算规则、实际消耗过程及其用量数据分开；有一份说明不代表资源权限已经生效。

Token、Compute 是计量口径，Reasoning Budget 是预算用途，可能用前两者计量。
不能当成三种可相加、互换的货币，也不能把同一笔推理消耗算两次。增加预算不等于模型本身修为提高。

### 功法与其他道法

道法内容位于通用依赖持续体下的信息制品分支。
功法、心法、术法、神通按实际含义及作品语境判断；不默认心法＝认知模型，也不按篇幅或文件名分类。

工程收录采用已有内容类：**解释型**讲概念与关系，**准则型**讲如何取舍，**方法型**讲怎样做；同时承担多种功能的完整内容保留**复合型**主类`dao-content`，不另起类型树。
例如，第一性原理的五步操作版是方法，胶水原则的复用准则是规约；不能只看它们被放在哪篇“思维模型”文章里。

功法品级另走一条轴：**黄阶 → 玄阶 → 地阶 → 天阶，每阶初级 → 中级 → 高级**。
这是用户选定的名称词表；已有规则草案，尚无校准后的判级量表，不凭名字、篇幅或步骤多少就给第一性原理等方法评天阶。

[功法JSON核心](../../metadata/gongfa/README.md)持续整理仓内方法与指定页面；当前数量与范围见该入口，[原六条](cultivation-ontology-taxonomy.md#首批功法登记)的ID、`r1`及确认主类保留。
当前条目均已按限定内容分类并给出人工暂定品级，记录任务族、理由、置信标签及反证；不是方法越抽象就越高级。
内容、来源快照、规则、人工初评与正式评级历史分开；规约仍待校准，作者判断不能代替实际验证。
一篇文章不一定是一门功法，换文件不自动换身份，改评级也不改变方法内容；修改核心方法则保留旧版并登记新内容版本。
功法说明需要什么操作能力，法器提供候选实现；可多对多替换，但必须满足环境、权限和副作用等条件。

Workflow 的方法规范属于方法内容，一次运行属于过程；这不证明所有阵法都是 Workflow。
阵法须分辨布设方法、具体布设及激活活动。Skill 按内容判断，Harness 软件实现与其采用的方法分开。
一份 Skill 混合解释、约束与步骤，可以整体归道法内容；不为填分类树而拆出三份原对象。
一次测量采用某方法，仍是同一次测量，关联所用方法即可，不再额外创造一个“方法施行过程”。

更细的归类见[下层判定边界](cultivation-ontology-taxonomy.md#下层展开的判定边界)：规定如何养成能力，与规定如何施展身法或铭刻源纹不同。
拿施技要领去练习，不改变那份内容的身份；一份方法同时包含服药炼化与炼体安排时，可保留共同上位主类。
学习口诀、训练施技、一次实际施展也不是同一所指；不能从“一个月后学会”倒造逐日训练日志。

### 丹方、炼丹与服药

[制备与施用链](cultivation-ontology-taxonomy.md#从原料到制备与施用)区分配方内容、具体原料、一次加工、丹药制品、服用及效果。
草被安排作原料，不因此变成另一种植物；实际加工成丹则须重新核对前后所指，不能强让产物沿用完整植株身份。
配方写到一种材料，不等于库存中的所有同类都已投入；工具和操作者参与，也不自动成为被加工的原料。
失败炼丹仍可能发生过实际加工，分离输出也可能原本就存在；得到产物不等于制出合格新品，吞服更不自动证明修为提升。
效果说明须保留条件与观察范围，不能截取“完美”或“三小时”就删去提前解除条件。
工程里只借鉴“制作、产物、使用、验收分别取证”的原则，不把程序或模型内容当成物质药材，也不冻结炼丹与构建的等式。

### 性质、读数与品阶

[性质与观测判据](cultivation-ontology-taxonomy.md#性质与观测的判定边界)回答的是：对象怎样、记录写了什么、据此能判断到哪一步。
同一把剑可以有长度、颜色和形状，但它们不是剑本身；写下“三尺三寸”也不会凭空产生一次实测。

- 形状不等于大小，长度/面积/体积不能混算；原作尺、寸等单位不自动换成现代制式。
- 苍白、像虎骨、地玄品阶分别涉及外观、比喻与分级，不从其中一个推定其余全部成立。
- 结构重新连接不等于功能全部恢复；某处修复，不代表其他部位或整个系统已经通过验收。
- 同颜色、同长度或同纯度不证明同一对象；换单位、改日志、重画图也不自动改变原物。

物理质量（mass）与“做得质量好”不同，前者不是模型权重或资源额度。
工程借用的是[从性质到读数与评价](cultivation-ontology-taxonomy.md#从性质到读数与评价)的分层，不把软件内容的大小、评分或耗时硬套成物体品质。

### 新生、再生与身份

[发育与再生判据](cultivation-ontology-taxonomy.md#发育再生与身份的判定边界)区分已有结构成长、新结构开始存在，以及缺损后新生补充/取代。
同一个人可以持续存在而某个旧部件被新部件替代；新旧部件同形、同位置，并不使它们成为同一所指。

- 改名、改选角色、替换部件与改变开闭状态不是同一类变化。
- 从11关开启到54关全开，开启存量净增43，不等于新造43个玄关；净化54关也不是只处理净增部分。
- 全开是所述启用前提，不等于特殊能力已经实现；成型、成熟和开始存在的时点也不能合并。

工程只借[分层身份证据链](cultivation-ontology-taxonomy.md#从旧结构到新结构)，不把模型更新叫作生物再生。
新部署可先验证再切换并保留回退；不要把小说“先吞旧结构”的顺序直接当工程规范。模型版本、运行活动、会话各守自己的身份契约。

### 法器

法器仍指工具和可调用入口，不是协议或权限。
实物工具归实物器物；指向程序内容的工具与接口实现统一归软件制品，一次调用则属于过程。
同一程序可以既执行任务又提供 API；两种用途不使它变成两个对象。

MCP/API 的规范内容与实现、部署绑定及使用过程分开。具体运行入口不能一律等同程序内容，更不等于协议或地址字符串。
两篇介绍同一工具的文章仍指向同一个工具；只有确有独立模块等所指时才分别登记，不靠拆 ID 凑分类。

实体细分见[生物与器物判据](cultivation-ontology-taxonomy.md#实体分支的判定边界)：按设计制成的兵器被拿来刻字，不会因此多出一件工具。
箱柜、内部空间、所装物件和库存表也不是同一个东西；设备组群要有物体成员依据，部署清单本身不等于一群物理设备。
这里只解释唯一树中的区别，不把全部法器都改成物质器物，也不以小说器物类替换软件内容、接口规范或会话。

器灵、化形与材料炼化须另查[身份与变化证据](cultivation-ontology-taxonomy.md#器灵化形与材料转化)。
有“灵”或人形不自动归为人类、角色或软件；想成为某物不证明转化完成，外形变化也不自动产生新身份。
角色已经成立但尚未实际行使，与只有获得角色的意愿不同；未读到结果不等于结果从未发生。

## 境界与战力

两者按项目的**评价含义**位于信息制品的记录与评价内容下，而不是模型能力本身。
性质、数值、结论与记录载体不同；原著中描述人物状态的同名词仍须保留其原义。

**境界**是按明确量表对指定对象作出的分级。须有量表版本、条件、证据和评定时间；缺量表不赋级。
不建立 AI 的炼气、筑基、元婴通用排行，不把人的掌握程度、模型能力和器物品阶混在同一量表上。
量表、准入门槛、测量方法与一次判定结果分别指认；测得更高等级也可能因年龄等条件未过关，第一关合格不等于全部考核通过。
原著对照见[传法到考核的证据链](cultivation-ontology-taxonomy.md#从传法到考核的证据链)，不据此宣称所有小说共享一套标准。

### 战力：具体任务的最终评价

**战力不等于修为。** 它评价具体任务交付，绑定任务、验收标准、结果证据与实际投入。
万魂幡不自带战力分数，魂魄也不因一次成功获得永久等级。

| 顺序 | 评估什么 | 判断依据 |
|---|---|---|
| 先看效果 | 是否正确、可用，完成目标且满足关键约束。 | 事先约定的验收标准与实际交付结果。 |
| 再看效率 | 同等合格且质量相当的结果用了多少投入。 | 时间、灵力与人类修正投入。 |

较快但不合格，不能胜过较慢但合格。
双方合格且质量相当时，一方各项投入都不更多、至少一项更少，才可直接判其效率更高；有取舍则保留各维度。
未观测不是零，未评定不是低境界，不编造通用战力总分。

## 用例检查

- **会话与集合**：魂魄是会话实例，万魂幡是会话类的外延，不是两个物质实体之间的部件关系。
- **模型与能力**：模型内容、运行实现、能力与评测分别判断；修为的版本归属不等于 BFO 直接承载关系。
- **方法与运行**：规范是信息内容，运行是过程；不是把一次执行画成某份方法文档的子类。
- **整体与组成**：一件器物、多件器物形成的组群、容器及库存信息分别指认；部分不等于下位类，位置不证明组成。
- **制作与使用**：实际制作、合格产物、服用和效果分别核验；失败不抹去已发生的过程，输出也不必是新生对象。
- **失效与总结**：实际失效与总结内容不同，不能从一次失效推出模型永久低境界。
- **框架与扩展**：下层难以归类时校准所指，不擅自替换 BFO 主干。
- **意向与变化**：意愿、实际变化和身份连续性分别核对；不凭章名或人形补造转化结果。

小说研究仍以《逆天邪神》最高权重，只对实际读取的章节和预览负责；作者、作品 ID 与读取范围一并核对。详见[分类验收判例](cultivation-ontology-taxonomy.md#分类验收判例)。
