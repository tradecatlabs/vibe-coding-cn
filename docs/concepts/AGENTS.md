# Concepts 目录 Agent 指南

## 目录职责

`docs/concepts/` 存放项目的核心概念与工程认知框架。

这里的文档回答：

- Vibe Coding 的基本概念是什么。
- 新手如何定义问题、拆解问题和构建系统。
- 工程方法如何从经验沉淀为可复用模型。

## 修改规则

- 继承 `docs/AGENTS.md` 的 README 结构契约：H1 后直接进入 `## 字多不看`，再按 `快速导航 -> 完整细粒度目录 -> 使用方式 -> 正文` 排列。
- 新增概念内容时，优先写入对应独立主题文档，并同步更新 `README.md` 索引。
- 新增同级主题 `.md` 文件前，必须确认它是稳定概念，并同步更新全仓链接、`metadata/taxonomy.yml` 和必要的 `redirects.yml`。
- 概念文档应优先使用稳定术语，避免同一概念多种叫法并存。
- 修仙领域以 `cultivation-ontology-taxonomy.md` 为唯一分类与语义契约入口；解释图层只引用，不维护并行的现实/知识分类树。
- V4 以用户指定的 BFO 2020 为固定前提，只在下层展开；保留原生 ID、定义与继承，不因适配困难擅自更换顶层。
- 区分类、实例与类外延：万魂幡引用会话类外延，不改成文档或物质聚合体；模型版本归属不等于 BFO 直接能力承载。未做公理验证不得宣称已完成。
- 领域类须在同一正文登记稳定 ID、工作定义、边界和依据，主父只由主树维护；下位类继承父定义，复合所指可留上位类，预览介绍不冒充完整规范实例；改名不换 ID，拆并留去向，不用用途交叉类或复制身份掩盖分类冲突。
- 领域主父细化须记录旧位置与理由、保留适用原生祖先，不挪用旧 ID；区分生物机体、设计构造、物体成员、组成和所在，CCO 只作判据参考，不整包导入或宣称等价。
- 制备细分须区分原料角色、规范、实际加工、物料输入/输出、制品和服用；输出不自动新生或合格，失败不抹去实际过程，功效条件不由一次表现替代；GDC 内容不作物质原料。
- 性质细分须区分承载者、品质、数值表述、观测记录、品阶与能力；量纲/测量范围/单位不足时不补值，局部结构恢复不证明整体康复；PATO 只作选定词义对照，不移植其根、过程特征或多继承图。
- 发育/新生/再生须有对应实际变化证据，整体、部分、角色与状态分层指认；成型不自动是首次存在，前提满足不当能力已实现；构造总量、状态存量、净变化及处理范围分开，不将叙事先后直接移植成工程部署顺序。
- 小说研究以《逆天邪神》最高权重，核对作者、作品 ID、版本与已读范围；保留原词，不以同题作品、章名、意愿或未读后续补造转化结果；叙事明确的胡诌不当真实机制。
- 器灵、形态与材料变化先核对所指、时间和身份连续性；不冻结心法/功法/阵法等跨书互斥叶类，不改变会话、集合、资源、权限和验收语义。
- 工程功法在既有道法类上维护收录视图，登记记录、内容版本、采用/组成关系与品级分开。
  四阶十二级是已批准的名称词表，不是完整判级量表；无规约与证据不作正式效果赋级，不将等级或具体条目塞进类型树。
- 功法品级与收录数据唯一维护于`metadata/gongfa/registry.json`；本目录只保留语义契约、链接及初始六条历史摘要。
  来源快照、内容版本、人工初评及正式评级历史分开；初评标记`provisional/expert_judgment`并保留理由、范围与反证。
  规约仍未校准、尚无正式效果评级；变更运行`make check-gongfa`与`make test-gongfa`。
- 不把一次性操作步骤放入本目录；操作型内容应放入 `docs/getting-started/` 或 `docs/references/`。
- 不在 README 正文中写 `和其他目录的边界` 或 `维护规则`；维护者规则只写本文件。

## 质量要求

- 每个概念先说明它解决的问题。
- 尽量给出使用场景、判断标准和简单例子。
- 不确定的外部事实必须标注 TODO，或放入 `research/` 等待验证。
- 修改后必须运行 `make sync-doc-toc` 和 `make test`。
