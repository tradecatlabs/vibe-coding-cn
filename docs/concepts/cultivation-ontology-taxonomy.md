# 修仙领域统一本体与分类设计（V4 BFO 草案）

## 字多不看

- **以 BFO 2020 为固定顶层，只在其下展开修仙领域类**；根为实体，其下只有持续体与发生体，不重新选择顶层。
- BFO 类保留原生 ID、定义与继承；`[域]` 为项目扩展，每类都有稳定 ID、工作定义、判定边界及依据，不冒充上游类。
- 实体下层区分生物机体、制成器物、兵器构造、收纳容器、物质组群和围护内部场所；组成、库存、用途不当类型继承。
- 品质下层区分形状、空间尺度、结构完整性、颜色与物理质量；长度/面积/体积不同，性质不等于读数、记录、品阶或能力。
- 内容与过程下层区分炼体/服药炼化、身法/源纹铭刻、准入/量表、访问授权/资源安排，以及研习、练习、测量与资格审定。
  制备另分原料角色、配方、加工、制品与服用；输出不自动等于合格新品，完成制作不保证服用效果。
- 机体结构发育另分新生与再生；整体、部分、角色和状态分别核对身份，改名不等于换主体，部件新生不等于整个人重新出生。
- 魂魄是单个完整 AI 会话，按会话过程建模；万魂幡仍是全部会话的概念集合，用同一会话类的外延表达。
- 修为归属于模型；模型内容、能力的直接承载者、推理过程和评测记录不能混同。灵力、境界与战力仍各守原义。
- [功法子域](#功法本体与品级)复用解释、准则、方法三条内容分支；条目、内容版本、来源、实际使用与品级分开。
  功法品级按用户确认采用《斗破苍穹》的**四阶十二级**；[JSON核心](../../metadata/gongfa/README.md)维护限定内容与来源，已完成人工分类与初评；判级规约仍未校准，初评不等于实测效果。
- 整体研究仍以《逆天邪神》最高权重；功法品级单独注明《斗破苍穹》来源，已读事实、人物主张与项目约定分开，不编造跨小说通用等级。
- 这是领域设计草案，不是已完成公理验证的 OWL 实现、运行架构或全仓本体。

## 范围与固定前提

本文是本领域**分类、定义与关系契约的唯一维护入口**；[修仙解释图层](vibe-coding-cultivation-model.md)只解释，不另画树。
适用范围限修仙领域，不迁移仓库目录、其他学科、固定事实镜像、全仓 metadata 类型或 Harness 算子契约。

用户明确要求“基于 BFO，在 BFO 下层展开”。此前助手擅自替换成 DOLCE 的方案已撤销，不能继续作为有效设计。
适配困难应通过类型、实例、类外延、承载、实现和记录之间的区分处理，不能以困难为理由换掉 BFO。

采用 BFO 2020 官方 `bfo-core.owl` 的上位类别及直接继承。树只展开本轮需要的分支，不表示删去上游其他类别。
本轮保存的源文件 versionIRI 为 `http://purl.obolibrary.org/obo/bfo/2020/bfo-core.owl`；来源和摘要见文末。
IAO 仅作信息本体参考，CCO 仅供器物设计与加工语义对照，PATO 仅供选定性质词义对照；不引入另一顶层，也不宣称导入整包或完成等价映射。

单根、单父、无环是本项目主分类树的额外约束。树表示“是什么”，成员、组成、使用、依赖、等级和来源另行表达。
类、个体及类的外延不是三个并行分类体系；不能因为使用集合语义，就再造一棵集合本体或知识条目树。

## 唯一分类树

带 `BFO_` ID 的节点是上游类，括号保留官方英文标签；`[域]` 为项目拟定的下层类。
这是类型树，不列具体人物、器物、模型版本、Session ID 或某次运行。未展开的 BFO 分支仍遵守上游定义。
当前为 101 节点、100 边：24 个 BFO 原生类、77 个领域类；最长路径仍为 9 层（实体为第 1 层）。这不是穷尽或互斥证明。
发育轮增补了两级下位；本轮功法子域复用既有类，增加内容登记和品级契约，不新增类型节点或迁移主父。
功法名称、版本与十二个等级值不画进类型树；过程子树总高度仍为3条边，不为层数插入无判定收益的类别。

### BFO 分支的含义与边界

| 分支 | 在本领域展开什么 | 不能误解为 |
|---|---|---|
| 独立持续体 | 人、实物、物质群体、身体部位、场所与空间边界。 | 所有有 ID 的东西；软件、模型内容不因可识别就变成独立持续体。 |
| 特定依赖持续体 | 依附特定承载者的品质、角色、倾向和功能。 | 任意属性字段、量值或报告；能力归属也不自动等于 BFO 直接承载。 |
| 通用依赖持续体 | 可由不同载体具体承载的内容或模式：道法、模型、软件、规范、记录。 | 实际载体、一次执行、集合外延或被记录对象本身。 |
| 过程 | 有时间部分且在某时有物质参与者的活动，例如交互、训练、施行、评定。 | 方法规范、消息内容、日志文件或一个纯数字标识。 |
| 过程边界及时间/时空区域 | 过程的边界与所占范围。 | 发生的过程本身；时间戳也只是指称时点的数据。 |

BFO 的 `immaterial entity` 不等于所有“非物理概念”；不把软件、魂魄或数学集合随意塞到该分支。
`object aggregate` 是物质聚合体，不能装入逻辑上的会话全集；`function` 位于 `disposition` 下，不与倾向并列。
`quality` 不直接依附过程；时长、Token 用量等过程计量由测量数据及其所指表达，不能生造“过程品质”。

实物器物要求按实际对象判断；“作为材料、工具或资源”是用途，不使同一物品变成三个身份。
具身主体群体只指物质成员的群体，不替代组织制度、所在地建筑或抽象成员名册。
活动场所指活动可发生的场所所指，不把整个洞府建筑都当无物质的 site；身体划分部位也不统包所有器官和修行构造。

这不是穷尽性、互斥性已证明的叶类表；**树上并列不自动声明互斥**。主父只由本树维护，说明表不重复父链。
复合内容按整体所指归到可靠上位类；若不可分的同一所指仍被主分类要求逼成两个身份，须修定义，不能假称证据不足。
上位 BFO 结构保持固定，缺证据的下层类可延后，不用“其他”或另一个顶层掩盖缺口。

## 领域类定义与稳定标识

ID 的作用域限本领域，不是全仓类型枚举或已发布的 OWL IRI。改标签不换 ID；拆分、合并或退役须保留旧 ID 去向。
既有 `ai-session` 保持不变。下表只给同一树的类作定义，不另设知识分类，也不把原著词直接当跨书同义词。

以下均为**项目工作定义**：O3 提供 BFO 上位约束，O7–O8 供器物与加工语义对照，O9 供选定性质词义对照。
N1–N28 提供已读线索及证据边界；N28 只支持新增品级词表，不改写已有类定义。
项目映射不是原著的本体宣言，也不是参考本体的完整翻译或等价实现。
“依据可定位”不等于该定义已通过独立语义审查；实例纳入仍须有来源和所指证据。

### 下层展开的判定边界

规范与过程的细分看的是**规范规定了什么、过程实际做了什么**，不是名称、使用者、一次用途或作品热度。
所有下位类都须满足父类定义；不能只读到身体增强的介绍，就假定已经取得完整炼体规范。

- **养成与施展不同**：规定怎样训练的安排与规定怎样施技的要领不同；拿要领去练习不改写内容身份。
  同一功法可以包含两者，锻龙戏也不能因为含有源术，就把整体和两套组成方法都登记成同一个叶类或三份原对象。
- **炼体与服药不是互斥划分**：一份规范可能同时规定服药炼化与躯体养成，整体可停在修炼方法规范。
  只有确有独立所指才登记内容部分；丹方的炼制步骤不因最终用于修炼就变成服药步骤。
- **规约的效力另验**：访问规则、额度与预算在内容上可细分，但不能用树上的类型标签证明授权或配额已生效。
  一份不可分的综合规约可留在规约与分配内容，不为同时涉及准入和授权而复制身份。
- **测量不等于准入**：测得某级不直接证明合格；须结合所适用的年龄、关卡等条件。
  同一次活动若兼有测量与资格判定，可按整体保留在测量与评定过程；不能凭三行结果断言三个独立过程。

未细化的分支不是空缺实例的默认容器，也不需要机械对称展开。
本轮不为每项规范配一个镜像过程类，不新增“攻击型/防御型法器”等外在用途分枝。
炼丹已补 N23 的局部直接材料；炼器、完整阵法及跨书制备规则仍待核验，不由这一个特例补齐。

### 实体分支的判定边界

- **机体与材料用途不同**：完整人类、非人动物与植株按机体指认；药材、战利品是用途或取得情境，不是生命种类。
  采收、搬运、死亡与解体分别判断；既不一变状态就换 ID，也不要求所有残体沿用原生物身份。小说族属不推出现实物种存在。
  BFO 的人为划定指约定界面，不等于人为切断；不能只因尸块是被切开的，就判作身体划分部位。
- **设计构造不同于临时用途**：制成器物要求制作或设计构造依据；刃式、发射式按结构及设计作用方式细分，不是“攻击时/防御时”的交叉标签。
  意图制造不证明实物已造出；已造出也不证明功能完好。只知器物为制品不等于已知制造者，N20 的器宗来源仍是人物推想。
- **组合器物不同于器物组群**：先判断整体的因果统一性，再判断是否以多个物体成员共同形成物质单位。
  复合构造可以仍是一件兵器；同时符合多个下位描述时保留可靠共同上位主类，不复制整体，也不虚构独立部件。
- **围护物、内腔和内容物不同**：箱柜是物体，内腔可有场所所指，所装器物不因位于其中就成为柜体部件。
  只有实际需要分别指认、且有边界证据时才登记；不为每个容器自动制造一套部件、场所与库存对象。

制成器物仍限于本树物体范围；CCO 的 Material Artifact 直接以 material entity 为上位，范围更宽，不能据参考关系宣称等价。
生物、人工改造与不同器物构造也不预设完全互斥；遇到同一复杂所指时用已有共同上位及关系表达，必要时重开下层定义。

### 制备与施用的判定边界

- **原料是情境角色，不是生命种类**：一株草被指定为原料，仍先按机体与当前构成判断；取消安排不要求毁掉植株。
  泛配方中的材料名、实际获安排的物料和本次真正投入的物料不同，不能按库存数补投入数。
- **参与者不全是输入物料**：操作者、器具及所用规范分别关联；“被使用”不等于被当作原料处理或消耗。
  物料输入/输出只用于有证据的物质加工，不把软件、模型或配方内容直接塞进去，也不虚构材料完全耗尽。
- **输出不必是合格新品**：分离可输出原本就存在的对象，制作也可能失败或留下残余物；输出身份、预期产物与质量分别核对。
  N23 提供从草材到丹丸及碎末的局部证据，不强留完整植株身份，也不由被发现顺序补出精确生成时刻或质量守恒账。
- **制成、服用、炼化与药效不同**：丹药的制作过程不等于随后吞服；吞服不自动证明能力养成、完全吸收或预期效果实现。
  成型药物限有物体整体性的制品；药液、散料与不同来历的玄丹留在有依据的上位，不靠名称强塞进丹丸类。
- **过程与成功分开**：有实际加工的失败尝试仍可属于制作过程，只有意向则不行；极短过程也不等于无时间部分的过程边界。
  同一整体兼含分离与成形时可保留物质加工过程；只有可独立指认的子活动才登记组成，不按每个动词另造过程。

CCO 的加工类有自己的适用范围：O8 的 Act of Material Artifact Processing 面向制成物的改变或保存，
Act of Manufacturing 还限定设施内批量生产及向消费者销售/分发的目的。
本项目允许自然草材和单次制丹，因此只借其加工/使用区分，不直接套用这些类或宣称等价；BFO 上位保持不变。

### 性质与观测的判定边界

- **先分承载者、性质与表述**：器物不是它的长度，长度不是“三尺三寸”这段内容；性质通过 `inheres_in` 依附合适承载者，记录通过 `describes` 描述所指。
  原文给出尺寸不等于叙述了测量活动；没有读数不证明性质不存在，也不为每个数字、形容词或字段造一个独立性质实例。
- **形状不等于大小**：几何相似变换可以保留形状而改变尺度；长度、面积、体积的维度不同，不能直接相加或互作下位类。
  本轮不按每个取值或器物种类另造性质叶类；不可分的复合表征可先留形态性质等可靠上位类。
- **范围与单位先于换算和比较**：剑的全长、刃长、表面积、材料体积、外形包络和内腔须分别指明，不能从同名“尺寸”合并。
  保留原词单位、近似程度和条件；作品中的尺、寸、斤两不默认等于现代制式，信息未给就保留未知，不补小数精度。
  这不妨碍保存原始陈述；量纲相同也不保证测量范围、条件和误差可比。
- **品质不是能力或好坏评分**：物理质量用 mass 意义；“质量上乘”、地玄品阶、承受攻击的能力与药力都须另判，不能共用一个质量数值。
  结构重接不等于韧性或功能完全恢复；病理实体、治疗过程也不因“受损”一词全部归入品质。
- **性质同值不证明身份相同**：同色、同长、同纯度都不能单独合并两个对象；相反，一份记录改单位、改图或纠错，也不自动创建新的承载者或性质。
  若原主体已确认灭失，历史记录仍可保存，但不能给它补当前性质；性质发生变化也不独自决定主体身份是否终止。

O9 的当前根 `characteristic` 包含实体与过程的特征，`color` 有两个直接父；这些不是本项目 BFO 品质的现成同义图。
本轮只参考选定词义，不导入其过程特征、多继承结构或全部 value 类；不把色调等组成维度误当颜色的种类继承。
其 `opacity` 定义含能力表述，也不能据此把全部透明、隐匿或发光能力归为 BFO 品质；仍须逐项核对品质与可实现实体的边界。

### 发育、再生与身份的判定边界

- **发育、新生、再生逐层收窄**：已有结构成长可只有发育；有新构造所指开始存在才判新生；还须有缺损及补充/取代关系才判本工作类中的再生。
  不给每个发育阶段另建方法/结果类，也不把每次尺寸或状态变化都当新实体出现。
- **阶段组成不当类型继承**：先固定所论结构及过程范围；部分过程属于新生类，不等于整段处置或发育都属于新生类。
  不凭内部未核验的微观新生改判整体，也不从整体被称作再生推出其中每一阶段都在新生。
- **先固定整体与部分**：同一个人可以经历旧部分终止、新部分形成；分别记录两部分与该机体的 `part_of` 时段及过程证据。
  同形、同位置、同功能或沿用称呼不证明新旧部分同一；反过来，也不能只因部件更替就断定整体已经终止。
- **角色与称呼分别核对**：改选随行者、改变称呼和更改授权是不同变化；称呼变化本身也不证明角色已经替换。
  不把两个人合为一人，不要求旧人死亡，也不把这些变化自动归入机体结构新生。
- **修复不是再生的同义词**：连接恢复、功能恢复、生成新构造与尝试修复分别取证；失败仍可有实际处置，不预支成功，也不从缺少新生证据推出肯定未新生。
  CCO 的 Maintenance 面向制成物及其设计品质/功能，按保存/恢复目的界定；不直接拿它覆盖本处机体结构发育或证明已恢复。
- **总量、状态、净变化与处理范围分开**：N27 的54关、初开11关、随后全开及净化遍及54关不是同一个计数。
  43是前后开启存量的净差，不是原文逐关事件日志；不由此新增43个玄关，不凭数字就将玄关统一定为物体、器官、孔洞或人为划分部位。
- **满足前提不等于实现结果**：N27 的全开要求应保留为启用条件主张；观察到全开不能直接补作特殊能力已实现，更不能把询问“是否就行”当充分性证明。
  临时/永久开启的说明保留对象、主张者与范围，不冒充无限未来的实测记录。

位于体内、参与处置或被称作“成长”不足以归入机体结构发育；外源施用可以触发发育，但施用物不自动成为所再生的构造部分。
这些是作品语境下的结构与身份判据，不是现实器官、细胞或基因机制结论。
玄脉/玄关更细的物质边界与类别仍须核验；不为补齐层级臆造实体种类、物料来源/去向或医学操作方案。

### 主分类的判定顺序

1. 先固定所指：类、实例、类外延还是描述内容；再固定语境、时间和身份，不从名称直接猜类。
2. 按 BFO 的存在方式确定分支，再检查域类定义；人参与过程不因此变成过程，人有角色也不变成角色。
3. 有更细分类的充分依据才下沉；复合整体与组成部分先区分，不能为了落到叶类而虚构独立所指。
4. 对能力先判倾向；满足功能的设计/生物演化依据时使用功能分支。承载者类型、模型归属与用途作为限定，不再造交叉主枝。
5. 角色依外在情境，倾向依内部构成；角色成立与角色实现分开，已成立的角色不必已经实现。
   想获得角色不证明其已成立；能力尚未实现不等于不存在，过程失败也不直接证明能力永不存在。

不同角色可依附同一承载者，但必须有可区分的情境与身份依据；不能为了让三个角色标签都入树而虚构三份角色实例。
同一不可分记录若符合多个下位描述，暂取共同上位主类并保留所指，不借标签复制记录；这不宣布所有下位类互斥。

## 功法本体与品级

### 功法的定义与收录边界

**本项目把可以独立引用、复用的认识框架、行动准则或施行方法收录为功法。**
这是工程内容的收录约定，不宣称所有小说都把功法、心法、术法或神通当同义词。
内容仍沿唯一树归入 GDC → 信息制品 → 道法内容；“功法”是受控收录视图，不新增横跨三条分支的交叉类或第二棵类型树。

收录须同时说清：解决什么问题、适用范围、可引用的核心内容、来源位置及内容版本。
名称或宣传语不是完整功法；纯认知模型可以只有概念与关系，不强行编成操作步骤。
书、文章和 Skill 包是组织或承载形式，不自动与一门功法一一对应；引用另一方法也不自动把它收成自己的组成部分。

具体任务预算、账号授权配置、一次运行日志、测试结果、模型权重、软件实现和工具地址不因有用就变成功法。
可复用的取舍准则可收录，某次安排或状态记录则另判；一份文章有多种内容时，先限定本条所指，不把整篇强塞进一个叶类。

### 功法类型与内容边界

下表是既有类的使用视图，不是新增类表；使用称呼不能替换稳定类 ID，也不宣布三类互斥或穷尽。

|---|---|---|---|
| 解释型功法 | `explanatory-content` | 给出概念、结构、关系或解释框架。 | 标题含“模型”不够；模型制品也不因此变成认知模型。 |
| 准则型功法 | `normative-allocation-content` | 给出可复用的行动要求、默认取舍及例外条件。 | 不是该上位类下的所有预算、协议和授权配置。 |

同一方法用于开发、诊断和学习，不因此变成三门功法；“被用于训练”也不自动把方法内容改成修炼安排。

功法是内容，登记条目是描述该内容的信息记录；记录可先按 `information-artifact` 指认，不把表格行当成方法本身。
一份内容被多个文件、链接或副本介绍，不自动多出多门功法；同名但核心内容、版本或来源不同，也不能直接合并。

形成独立新方法或发生拆并时保留原 ID 及去向，不挪旧 ID 给另一所指；单独修改评级结论不改变功法内容、主类或版本。
新内容版本不自动继承旧版本评级。已有评级被纠正时保留历史结论与纠正依据，不把当前显示值当作永恒属性。

### 功法关系与法器边界

- **属于哪类**用 `instance_of` 说明内容的类型；具体功法不是方法类的子类，等级不是内容类的父节点。
- **包含哪些内容**用有证据的 `part_of`；仅链接另一篇资料、同时提到某方法或推荐配合，不足以证明组成。
- **采用什么方法或原则**用 `adopts`；须能定位所采用的内容，不推出类型继承，也不等于整份被采用内容成为组成部分。
- **一次活动用了什么**用过程指向内容或工具的 `uses`；是否符合方法要求另看 `conforms_to`，一次运行不是功法本身。
- **方法需要什么能力**先记录前提与操作能力要求，再按场景选择法器实现；不直接把工具品牌当成方法种类。

功法与法器按能力要求建立多对多联系：同一功法可以选不同实现，同一法器也可支持多门功法。
替换须满足输入输出、环境、权限及副作用等约束；确有不可替代依赖时才绑定具体工具与版本。
工具建议不自动成为唯一依赖，未绑定固定法器也不表示执行无需主体、资源或权限；提供能力的说明不冒充已验证能力实例。

### 人、模型、会话与集合

- **人类修士**：人这一所指归人类主体；使用者、审核者等角色依附人，不因换角色而换人。
- **模型**：可识别版本的已训练模型内容归模型制品。权重文件副本、承载硬件、可调用接口和一次推理分别判断，不能把 API 当模型。
- **魂魄**：单个完整 Conversation / Session，按 **AI 会话过程**建模，领域类型标识为 `ai-session`。
  它涵盖会话建立及其中的交互活动，不缩成一次模型调用、单条消息、Memory 或日志文件。
  来源命名空间与 Session ID 联合确定身份，必要时包括工具、服务实例及账号范围；恢复和换模型不自动产生新会话。
  若来源会复用 ID，需追加可核验的创建代次或不可复用来源标识；不能仅凭相同字符串合并，也不能凭自造时间戳拆分。
  暂停前后的活动可属于同一会话整体；明确 fork 则保留新 Session 身份及来源关系。未发生的计划活动不冒充事实。
- **万魂幡**：跨 Pi、Claude Code、Codex 等工具的全部 AI 会话的概念集合，直接指上述 `ai-session` 类型的外延：
  **万魂幡 = Ext(ai-session) = 所有属于 AI 会话类型的会话实例所组成的集合。**

万魂幡没有被改成“描述集合的文档”，集合成员也不是概念标签，而是实际会话。
这里不把类外延再当作 BFO 个体实体，因而不需要新建 `Abstract`、集合实体或物质聚合体分支。
“某魂魄属于万魂幡”用实例属于 `ai-session` 类表达，不把魂魄画成万魂幡的子类。
这不是另一棵树：集合定义只引用同一主树中已有的会话类。

已知清单、某账号授权子集、某时刻查询结果都不等于全集。未登记或不可访问不等于不存在；集合定义不授予读取权限。
单纯创建一份会话描述或空模板不证明会话已经发生；会话实例需有来源系统的建立或交互证据，不能只凭一个 ID 虚构过程。
已结束会话仍可被记录指称，重新导出转录不产生新魂魄；跨来源身份不能仅凭相同 ID 字符串合并。

### 模型归属与 BFO 直接承载

**修为仍指模型能力，不改成会话能力、评测报告或整套工具系统的任务表现。**
但“归属于哪个模型版本”和 BFO 的 `inheres_in` 是两种不同关系，不能为省事混成一条。

- 模型内容在通用依赖持续体下；能力按倾向及有依据的功能分支表达，不另建与功能交叉的“模型运行能力”主类。
- 能力的 BFO 直接承载者必须是合适的独立持续体，例如实际实现该模型的计算系统，而不是 GDC 模型内容本身。
- 用领域归属关系关联能力与模型版本，用实现关系说明该计算系统如何实现该模型；不将两者声明为同一个对象。
- 比较模型修为时须约束任务族、运行配置、工具、上下文与预算；不能把工具加成或整个系统效果全部归给模型。
- 多个运行实现可实现同一模型内容；能力实例依附各自承载者，评测结论是否可推广到模型版本须另有证据。

这一区分服务于既有真实所指，不要求每次提及模型就自动新建硬件、能力和报告的全套对象。
来源无法识别实现或模型版本时保留未知，不制造虚假承载关系，也不把测试报告当成能力本身。

### 道法、法器与实际施行

道法内容、模型内容和软件制品都在 BFO 通用依赖持续体下展开，但它们不是同一种内容。

| 情况 | 必须核对什么 | 不能直接推出什么 |
|---|---|---|
| 被称为器灵、能够说话或呈人形 | 指称的主体、身体/承载依据，以及与器物是同一、组成还是其他关系。 | 不能只凭名称归入人类主体、BFO Role、GDC 或 immaterial entity；会对话也不等于项目中的 AI 会话过程。 |
| 对象外形发生变化 | 前后所指是否连续存在，变化的是性质、组成还是对象身份；固定证据所指的时间。 | 不自动新建另一对象，也不因外貌变成人形就赋予人类类型。 |
| 材料被使用、消耗或炼化 | 仅承担用途，还是原物终止并有新产物；组成连续性与整体身份分别核对。 | 不按用途复制材料身份，也不强行让所有产物沿用原料 ID；新生成须有依据。 |
| 愿意、计划或被建议成为某物 | 主张者、目标、叙述时间与实际过程/结果；角色若涉及外在情境，还须有成立依据。 | 不以意愿、条件句或章名证明转化完成；未核验结果也不等于确认没有发生。 |

N12 的可见开头涉及相关意向问句及人物反应，尚不足以据此填入完整转化过程、结果或器灵存在方式。
N13–N15 的预览也未提供所需的化剑或毒灵机制；目录、百科和检索回答不能补齐付费正文。
原著中的灵魂、器灵按其语境研究，不改写项目“魂魄＝完整 AI 会话”的既有约定。

### 修为、灵力、境界与战力

| 概念 | 下层位置或表达 | 保留的边界 |
|---|---|---|
| 修为 | 倾向或有依据的功能，以及模型版本归属；直接承载关系按上一节处理。 | 不是评测数据、会话属性或系统总效果，一次回答不代表全部能力。 |
| 灵力 | 生效的资源分配内容、预算规范、实际消耗过程与用量数据分别表达。 | 资源使用权、设备、额度、预算和账单不相互替代，不能仅凭一条记录断言实际分配已生效。 |
| 境界 | 记录与评价内容 → 分级结论。 | 绑定被分级对象、量表版本、条件、时间和证据；没有量表不赋级，不制定通用 AI 修仙排行榜。 |
| 战力 | 记录与评价内容 → 任务评价。 | 绑定任务、验收、交付结果与实际投入；一次成功不产生永久等级。 |

将境界、战力按本项目的**评价含义**定位，不把原著中描述修士状态的同名词自动改成报告。
评价内容不等于存放它的文件，性质不等于测量数值，数值也不必都实体化为本体节点。

Token、Compute 是计量口径，Reasoning Budget 是预算用途，可能以前两者计量；三者不是互斥、等价或可随意相加的货币。
预算、可用额度和实际用量分栏，注明单位、时间窗、计数规则及来源；同一笔消耗不能因推理用途重复计量。
没有配额记录也不能虚构配额；一份分配说明是否有效须核对实际授权与系统状态，不能只凭标题认定。

战力**先验收效果，再比较效率**。较快但不合格不能胜过较慢但合格。
双方合格且质量相当时，一方各项投入都不更多、至少一项更少，才可直接判效率更高；
存在取舍则保留时间、资源、人工投入各维度，不编通用总分。未观测不是零，未评定不是低境界。

## 树、关系与知识记录的契约

### 分类与关系不能互相替代

下表使用便于阅读的关系简记，不是已实现 API 或已导入的 OWL 属性。
`inheres_in`、`is_carrier_of`、`concretizes`、`realizes` 等的方向参考 O3 第 2.38、2.52、2.53、2.43 节；实际映射须保留完整参数与条件。
物体成员另参考 O3 第 2.19–2.21 节；不能把成员关系泛化为逻辑集合成员、在某处出现或被某清单收录。

| 表达 | 方向与含义 | 约束 |
|---|---|---|
| `parent` | 类 → 唯一主上位类 | 单根、单父、无环；BFO 原生继承不改写，实例不作类父节点。 |
| `instance_of` | 实例 → 有依据的主类 | 会话实例属于 `ai-session`；属于其祖先不算双父，类型 ID 与实例 ID 分开。 |
| 万魂幡的成员语义 | 会话属于 `ai-session` 的外延 | 不是物质部件关系；不伪造指向“集合实体”的 BFO 对象属性。 |
| `inheres_in` | 特定依赖持续体 → 非空间区域的独立持续体 | 不把模型 GDC 内容直接填成能力承载者，也不把记录值当性质实例。 |
| `is_carrier_of` | 非空间区域的独立持续体 → GDC，带时间 | 硬盘承载内容；载体不是内容，保存同一内容的副本不自动增加一个模型。 |
| `concretizes` | 特定依赖持续体或过程 → GDC，带时间 | 例如依附载体的具体物理性质/模式或相应过程；须核对共享的内容，不能直接把硬盘物体当此关系主语。 |
| `realizes` | 过程 → 可实现实体 | 实现角色、倾向或功能；需相关过程类型及承载者条件，不把规范或模型内容填成可实现实体。 |
| `attributed_to_model` | 能力实例 → 模型制品版本 | 领域归属而非 BFO 直接承载；须有实现、条件与证据，报告主张不能冒充已证实的能力关系。 |
| `describes` | 信息内容 → 所指 | 记录/评价或能力主张描述对象，不替换对象；主张者、时间及支持状态留在证据中。 |
| `participates_in` | 合适的持续体 → 过程，带参与时间 | 人、计算系统、模型内容等参与；会话本身是过程，不能因其 ID 持续存在而改作持续体参与者。 |
| `uses` | 过程 → 所用持续体 | 采用方法内容或使用工具不产生另一过程身份；使用不自动证明遵守规范。 |
| `has_material_input` | 物质加工过程 → 实际作为待处理物料参与的物质实体，限定参与时段 | 领域简记，不是上游 BFO 属性；计划物料、旁观者、所用工具或 GDC 内容不自动成为输入，不预设完全消耗。 |
| `has_material_output` | 物质加工过程 → 经该加工产生或分出的物质实体，限定过程与输出时段 | 须有实际输出证据；可含残余物或原已存在的分离对象，不等于新生、合格、获授权或全部预期效果已实现。 |
| `implements` | 指定实现 → 模型内容或规范 | 领域实现声明；物质系统、软件内容分别指认，不等价于具体化、能力承载或 `realizes`。 |
| `conforms_to` | 指定实现或执行 → 规范 | 需要符合性证据，工具名、调用成功或用途说明都不足以证明。 |
| `part_of` | 组成部分 → 整体 | 持续体组成需限定时间，与发生体组成分别核对；位置、同一时间范围或被某会话触发都不能单独证明组成关系。 |
| `member_part_of` | 物体 → 物体聚合体，带时间 | 物体成员须满足互不重叠且穷尽该聚合体的划分条件；器物零件、库内出现或名册收录不能直接替代。 |
| `affiliated_with` | 主体 → 已消歧的组织所指 | 不把物质群体、制度内容、名册与建筑当同一组织实体，具体组织建模不足时保留未决。 |
| `located_in` | 非空间区域的独立持续体 → 同类允许的所在实体，带时间 | 模型内容不直接位于机房，应描述承载设备的位置；部署归属不冒充空间位置。 |
| `adopts` | 道法内容 → 被明确采用的道法内容 | 须定位采用的原则、解释或方法；仅引用、相似或推荐配合不足，不推出类继承、整体包含或效果已实现。 |
| `requires` / `contrasts_with` | 方法 → 前提；同维度对象间比较 | “有帮助”不等于必要条件；声明前提不等于已满足，比较不生成第二主树。 |

例如：物质硬盘承载模型内容，相关物理模式将其具体化，推理过程实现运行系统的能力；三者不能互换主语与宾语。
实例数据未提供这些所指时宁可保留未知，不为补齐关系图自动制造设备、能力或具体化记录。

### 最小记录要求

1. **类型**：复用上表稳定 ID 和主树唯一父节点，保存名称、定义、纳入与排除条件及来源；不得以另一份父链覆盖本树。
2. **对象**：稳定身份、主类、身份判据；消息 ID、文档 ID 与 Session ID 不混用，不为每个名词自动造实体。
3. **词义与语境**：保存原词、作者、平台作品 ID、版本或项目语境；同题作品不能仅凭书名合并，同义合并需依据。书内成立不推出现实存在。
4. **主张与来源**：保存出处、位置、实际读取范围、主张者、时间及支持状态；区分叙述、人物观点、二手评论和项目设计，注明事实陈述、意向或条件，不能将未核验补成否定事实。
5. **量与评价**：绑定对象、单位、计数规则、量表或验收条件、时间与证据；预算和实际分开，不将未知补零。
   涉及性质比较或换算时再明确承载者、几何范围、原始单位/近似程度与换算前提；只有表述而无测量证据时，不补方法或实际测量过程。
6. **演化与权限**：改名不换 ID，分类纠正留理由，拆分合并留旧 ID 去向；收录不授予访问权限，不收集未授权正文或凭据。

知识记录描述同一树上的类或实例，不另设 `concept / practice / tool_reference / failure_mode` 分类树。
需要研究记录本身时可以描述其信息内容，但不能以此替换会话、集合或能力。
未来 JSON 只能承载获准结构化的领域记录，不取代教程、原始研究、事实镜像、metadata 索引或 Harness 契约。

## 分类验收判例

以下是预期语义判定，不是已运行的自动语义测试或独立评审。

| ID | 输入或变化 | 必须得到的结果；须拒绝的错误 |
|---|---|---|
| C01 | 跨来源或来源复用同一个 Session ID | 跨来源不能合并；同源复用须核对创建代次。不能凭字符串合并，也不能凭自造代次拆开。 |
| C02 | 会话恢复、换模型或重新导出 | 来源身份未变则仍是同一会话整体；不是每轮都新建魂魄。明确 fork 保留新身份。 |
| C03 | 万魂幡、已知清单与一个魂魄 | 全集用 `ai-session` 类外延表达；清单只是记录，魂魄是实例；拒绝物质聚合体、描述文档替代集合。 |
| C04 | 模型副本、量化版本、部署与推理 | 相同内容副本不复制模型；量化等内容变化另判派生版本，名称相同不保证身份相同，API 不当模型。 |
| C05 | 模型能力与新评测报告 | 直接承载与版本归属分开；满足功能定义时使用功能分支，不另造同一能力；报告描述能力，不成为能力或承载者。 |
| C06 | 天毒珠多用途、工具多篇介绍 | 一个对象，多项用途与描述关系；不按用途或文章数复制身份。N1。 |
| C07 | 玉石、功法及内部技法 | 载体与内容不同，内容组成不是类型继承。N4、N10。 |
| C08 | 心法标题、Workflow 规范及实际玄阵 | 先读词义；不默认心法＝认知模型、阵法＝Workflow。规范、布设与过程分开。N6。 |
| C09 | 同一软件执行任务并暴露 MCP/API 入口 | 仍为一个软件制品，不按两种用途复制身份；规范、部署入口与一次调用另外按真实所指判断，符合性和权限另验。 |
| C10 | GPU、配额、预算及实际用量 | 物理设备、生效分配、预算与用量分开；分配记录不自动证明权限生效。 |
| C11 | 一笔推理消耗同时按 Token 统计 | 用途不变成第二笔消耗；不同口径不直接相加或互换。 |
| C12 | 功法重数、玄力阶段与无量表的 AI 等级 | 绑定各自对象和量表；缺量表不赋级，不凭同名等级横比。N4、N5。 |
| C13 | 玄关实际全开，观察者只探知部分 | 状态、观测与主张分开，不让错误观测覆盖事实。N3。 |
| C14 | 宗门、所在地、弟子及容纳人的器物 | 成员、制度、场所与器物按所指区分，用归属/所在/容纳关系而不是类型父链。N2、N7、N8、N11。 |
| C15 | 材料用于炼制；假设工具充当阵眼 | 用途不自动改变对象身份，实际转化须有身份依据；软件用途标签不能随意冒充 BFO Role 实例。 |
| C16 | 攻击手法、一次 Prompt Injection 尝试及越权 | 方法内容与实际过程不同；是否成功越权取决于结果证据，不能凭尝试断言成功。 |
| C17 | 幻觉失效与总结文章 | 实际失效过程与描述内容不同，不据此给模型永久低境界。 |
| C18 | 更快但不合格；双方合格但投入各有长短 | 不用速度抵消验收失败；有取舍时保留多维结果，不编通用战力分数。 |
| C19 | 下层术语暂时难以映射 | 校准所指及下层扩展，保留未决项；不得擅自替换 BFO 或另加 Abstract 顶层。 |
| C20 | 一份 Skill 同时包含解释、约束与步骤 | 内容整体可归道法内容；只有存在独立所指才登记内容部分，不为落到叶类复制三份原对象。 |
| C21 | 一次测量采用指定方法 | 同一测量过程关联所用方法，不因“施行了方法”再创建一个过程或平行主类。 |
| C22 | 器物临时用途、内部能力及设计目的 | 外在情境角色与内部倾向分开；功能还需设计/生物演化依据，不能只凭“用来做”断定。 |
| C23 | 类型改名、拆分、合并或会话 ID 复用 | 改标签不换类型 ID，语义拆并留旧 ID 去向；类型 ID 的稳定规则不能替代实例生命周期核验。 |
| C24 | 禾菱成为毒灵的意向问句与相关章名 | 只登记可见主张，不补造转化完成、过程或存在方式；未读后续不代表从未发生。N12。 |
| C25 | 假设器物改变外形，或材料被消耗并形成产物 | 核对前后身份、性质与组成；不凭人形赋人类类型，不自动拆身份或强留原料 ID。不是本轮已核验情节。 |
| C26 | 搜索返回同题但不同作品 ID，或以章名补正文 | 核对作者、作品 ID、版本及实际范围；其他作品不并入原作，目录与摘要不充当转化结果证据。N13–N15。 |
| C27 | 身法要领、听讲、学习时间预测及一个月后的一次表现 | 规范、研习、预测与实际过程分别指认；不复制人物，不从残影造新主体，不补整月训练日志或全部能力。N19。 |
| C28 | 章名为大道浮屠诀，后章开头介绍身体力量与韧性作用 | N17 章名不证机制；N18 只支持炼体方向的角色主张与候选词义，未取得完整规范，不补全高阶数值或已实现效果。 |
| C29 | 十七岁入玄四级未过关，十五岁入玄二级过关 | 按各年龄门槛判定，与 N5 结果一致；较高读数不自动合格，第一关合格不等于全部入门资格成立。 |
| C30 | 可参悟残卷一个月，但未确认其他处置权 | 内容访问规约不自动给出转交、转授权或所有权；实际查阅和理解另验，不把一个月无依据换成固定天数。N4。 |
| C31 | 凤神丹服用炼化与取出炎龙玄丹 | 指示内容、物件和过程分开；不把服药炼化当炼丹制造，不因同含“丹”字或可吸收力量就断定同种药剂。N4、N19。 |
| C32 | 秦玉回忆周元被放在祭坛作阵眼 | 保留回忆主张和语境；人不因此变法器，角色须按外在情境另判，不推自愿职责；不外推法器阵眼机制。N16。 |
| C33 | 假设只修改任务预算，实际配额与历史用量未变 | 只更新预算内容及版本关系；不能由预算变更推出额度扩容、权限生效或历史消耗改写。工程设计场景。 |
| C34 | 假设同一不可分方法兼含服药炼化与长期躯体养成 | 主类可保留修炼方法规范；两种描述不强制拆成两份身份，也不宣布所有修炼方法都互斥或已穷尽。设计场景。 |
| C35 | 测玄石同屏给出年龄、玄力和合格性 | 可把整个活动保留为测量与评定过程；没有内部机制证据不造三个子过程，测量方法也不变成第四个过程。N5。 |
| C36 | 假设已实际执行测量但没有有效结果，且无缺测判定规则 | 保留测量活动及失败/未决状态；不把读数补零，也不把无法判定补成低境界或不合格。设计反例，不是 N5 已发生情节。 |
| C37 | 两株星隐草显现后被连根采下，并谈及将来淬炼星隐丹 | 区分完整植株、观察、采收与未来产物；不能因先前看不见就判不存在，也不将两株合成一株或宣称本章已炼成丹药。N21。 |

### V4 下层收敛记录

2026-09-30，继续在 V4 上落盘定义与稳定标识，不另起版本树。原生 BFO 分支不变，领域节点由 30 收敛为 25。
删除的是交叉分类入口，不是其所指、用途、能力或原著术语；数量减少本身不是质量证明。

| 原草案节点 | 当前去向 | 原因 |
|---|---|---|
| 执行工具软件、调用入口软件 | `software-artifact`；用途、接口实现和部署绑定分别说明。 | 一个软件可兼具两种用途，不应被迫两份身份；运行入口也不能一律替换成程序内容。 |
