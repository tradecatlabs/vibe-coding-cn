# vibemathing/vibe-mathing-cn-public 深度研究

## 研究级别

- 当前级别：L2 源码/结构深度研究。
- 研究对象：`vibemathing/vibe-mathing-cn-public`。
- 研究证据：固定 `main` 快照、`raw/` 一手材料、源仓库 `bash scripts/check.sh` 输出和本地隐私审计。
- 当前快照提交与树哈希：见 `IMPORT_MANIFEST.yml`。

## L2 结论

这个项目的核心不是“让模型直接解数学题”，而是建立一个不轻易承认答案的研究流水线。它通过契约、状态、证据和工具边界，把自然语言候选限制在可复查的研究流程中。

## 结构证据

### 1. 问题、尝试和结果分层

- `problem-library/` 负责来源问题、公共问题身份和候选观察。
- `research/` 负责研究尝试、输入、声明和产物。
- `result-library/` 负责通过验证后的结果和派生索引。
- schema 和验证器共同限制记录状态，避免把来源状态直接当成数学结论。

这是一种适合 Agent 系统的状态隔离：候选可以大量产生，但只有满足准入条件的证据才能进入稳定结果层。

### 2. 证据不是装饰，而是准入条件

项目把数值检查、符号检查、人工审查、kernel check、反例检查和陈述忠实性分开。这样做避免用一个“通过”字段掩盖证据类型不同、强度不同和适用范围不同的问题。

可迁移的工程含义是：任何 Agent 结论都应记录“依据是什么、由谁或什么工具验证、验证覆盖到哪里、还缺什么”，而不是只保存最终文字。

### 3. 工具调用被限制在有界运行时内

`scripts/vibe_mathing/runtime.py`、工具检查脚本和 canary 测试共同体现了几个边界：

- 子进程必须有 timeout。
- 输出和输入必须有大小上限。
- 运行要有资源预算和停止条件。
- 失败必须返回明确状态，不能被空输出伪装成成功。
- 运行回执不能自动升级成数学 Result。

这部分最适合迁移到当前项目的 Agent 工具执行和质量门禁。

### 4. 公共边界和供应链边界分开

- `scripts/validate_public_boundary.py` 检查公开仓库不应携带的路径、凭据、运行产物和私密材料。
- `vendor/sources.lock.json` 和 `vendor/` 维护外部来源、固定版本和许可证边界。
- `.codex/skills/` 只保存当前项目适配后的 active skills，不直接激活上游内容。
- `problem-library/raw/`、`literature/files/`、`vendor/upstream/` 等可重建或高风险材料保持本地边界。

这说明研究快照也应把“能阅读”与“能执行”分开。当前项目只保存安全快照，不执行其中的脚本。

## 隐私审计结果

- 当前 `main` 快照：未发现本机私人路径、硬编码凭据、私钥或 Token。
- 源仓库可达旧历史：曾有审计报告把本机路径写入输出 JSON；该历史不复制到父仓库。
- 环境变量：代码读取的是通用控制变量和工具配置变量，未发现提交的实际环境变量值。
- Git 身份：源仓库历史使用 GitHub 匿名地址或技术地址，未发现真实个人邮箱。

因此，本次导入采用“当前文件快照”而不是“源仓库历史镜像”。

## 迁移边界

### 可以迁移

- 候选、尝试、结果和证据的状态分层。
- 工具调用的 timeout、资源预算、输出上限和失败回执。
- 固定提交、树哈希、来源清单和可复查快照。
- reference-only 供应链和 active capability 的分离。

### 不能直接迁移

- 数学领域的 ProblemContract schema。
- SymPy、SMT、Lean 的具体工具准入规则。
- 数学 Result 的独立性和陈述忠实性判定。
- 源仓库的外部问题目录和文献缓存。
- 源仓库的 Codex skill 触发方式和领域命令。

## 最小验证闭环

1. 源仓库工作树干净。
2. 用 `git archive main` 生成快照。
3. 对临时快照做路径、凭据、软链接和生成物扫描。
4. 记录提交号、树哈希、文件数和归档哈希。
5. 父仓库运行研究域、链接、目录、metadata 和 AI 引用门禁。
6. 只有经过人工审查后，才允许把稳定机制下沉到当前项目。

## 待验证问题

- 证据状态模型能否抽象成不依赖数学领域的 Agent Result Contract。
- 工具成熟度 registry 能否与当前项目的 skills 和 external resources 统一。
- 失败回执和候选隔离是否能减少当前项目的 AI 生成幻觉与过度承诺。
