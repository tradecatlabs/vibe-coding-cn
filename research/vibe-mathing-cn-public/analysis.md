# vibemathing/vibe-mathing-cn-public 研究分析

## 本轮结论

`vibemathing/vibe-mathing-cn-public` 值得作为独立研究域加入当前项目，但只应作为“数学研究与可信验证工程”的参考对象，不应直接变成当前项目的数学计算运行时或 active skill 来源。

它最有价值的部分是把 AI 生成的候选、研究尝试、计算输出和最终结论拆开，并要求最终声明绑定可复查证据。这个思路可以迁移到当前项目的 Agent 任务、工具调用和质量门禁中。

## 本地证据

- 源仓库：`https://github.com/vibemathing/vibe-mathing-cn-public`
- 固定来源分支：`main`
- 当前快照提交：见 `IMPORT_MANIFEST.yml`
- 源仓库完整检查：`bash scripts/check.sh` 通过。
- 源仓库主要结构：`problem-library/`、`research/`、`result-library/`、`governance/`、`.codex/skills/`、`scripts/`、`fixtures/` 和 `vendor/`。
- 当前快照不包含源仓库 `.git`；源仓库旧历史中的本机路径不进入当前项目。

## 对标拆解

| 项 | 观察 |
|:---|:---|
| 参考对象 | `vibemathing/vibe-mathing-cn-public` |
| 它解决的问题 | 防止 AI 把候选推导、运行成功或自然语言解释直接冒充数学结论。 |
| 核心机制 | ProblemContract、Attempt、Result、Evidence、ResearchBundle 和有界运行时。 |
| 可信来源 | 固定 schema、测试 fixture、工具回执、形式化检查和公开边界验证。 |
| 失败处理 | 失败、未确定和证据不足保持显式状态，不强行生成答案。 |
| 供应链处理 | 外部工具和 skills 通过固定来源、许可证和能力成熟度进行隔离。 |
| 可迁移做法 | 将“候选”和“已接受结果”分层；给工具加 timeout、输出预算、停止条件和失败回执。 |
| 不可迁移条件 | 当前项目不是数学证明系统，不能把 SymPy/Lean 通过测试等同于一般数学正确性。 |

## 改良迭代

| 改良目标 | 源仓库启发 | 当前项目的适配方向 | 验证指标 |
|:---|:---|:---|:---|
| 候选隔离 | CandidateObservation 不直接进入 Result | 研究资料、外部资源和 active skill 分层管理 | 未经审查的候选不会进入稳定索引 |
| 工具边界 | 工具登记成熟度和能力边界 | 为高风险 Agent 工具记录输入、输出、权限和失败语义 | 工具调用具备 timeout、预算和回执 |
| 证据链 | Result 必须绑定独立、完整、有效证据 | 研究结论绑定原始来源、验证命令和观察日期 | 每条重要结论都能回到一手证据 |
| 公共发布 | 发布资产不能携带私密路径和运行状态 | 同步快照前执行隐私、凭据和生成物扫描 | 父仓库快照不含 `.git`、本机路径和密钥 |

## 可迁移清单

- 把“模型提出了什么”和“系统承认了什么”分开。
- 给 Agent 工具建立能力状态，而不是只记录工具名称。
- 给长任务设置超时、输出上限、资源预算和明确终止状态。
- 让失败记录成为一等结果，不用空结果掩盖失败。
- 用固定提交号、树哈希和来源清单保证研究快照可复查。
- 对外部 skills 和供应链材料保持 reference-only，不自动激活。

## 不可迁移清单

- 不把数学 `Result` 模型直接当成当前项目所有文档的统一数据模型。
- 不把 `symbolically-checked`、`numerically-checked` 或测试通过写成一般证明。
- 不把源仓库的 `.codex/skills/` 复制到当前项目顶层并自动执行。
- 不把问题目录、文献缓存、运行记录和模型资产带入父仓库。
- 不在当前项目复刻完整数学平台；只吸收可验证的工程机制。

## 验证动作

| 动作 | 成功信号 | 失败信号 |
|:---|:---|:---|
| 用固定 `main` 生成快照 | 文件数量、树哈希和 manifest 一致 | 混入未提交文件或本机缓存 |
| 扫描快照隐私边界 | 无私人路径、凭据、`.git` 和运行产物 | 出现本机路径、Token 或日志 |
| 抽取一个 Agent 工具门禁模式 | 能定义输入、权限、超时、输出和失败回执 | 只有“工具执行成功”没有边界 |
| 抽取一个证据链模式 | 研究判断可回到原始来源和验证动作 | 结论只能回到模型自述 |
| 运行父仓库质量门禁 | `make test` 通过且索引完整 | 研究目录破坏根仓库文档检查 |

## 沉淀判断

当前先保留在 `research/`，等级为 L2。若后续验证表明“候选隔离、证据回执和有界工具执行”能跨数学领域和普通 Agent 任务复用，再分别沉淀到 `docs/workflow/`、`docs/references/` 或 `skills/`；不要直接搬运源仓库的领域模型和运行代码。
