# GATE-0002 数学成果晋升必须有充分证据和独立验证

本门禁执行 [`VIBE-MATHING-SPEC v0.1`](../../standards/VIBE-MATHING-SPEC-v0.1.md) 的 R1 候选隔离、R2 验证准入和 R3 证据守恒；架构依据见 ADR-0000。

## 阻止条件

满足任一条件即阻止进入完整解视图：

- Result 不是 `proof` 或 `counterexample`；
- proof 的 outcome 不是 `established`，或 counterexample 的 outcome 不是 `refuted`；
- 当前有效证据没有独立的 `human_review`、`kernel_check` 或适用的 `counterexample_check`；
- 结果依赖 `kernel_check` 作为直接验证，但没有当前有效且独立的 `axiom_escape_audit`；
- verifier 未注册、能力未授权、output policy 不匹配，或其 trust domain 与 generator 相同；
- Result 与 Attempt 引用不同的 canonical Problem，或独立 verifier 等于 Attempt.generator；
- 准入证据不在 `research/artifacts/` 可信根、经过 symlink/路径逃逸、文件缺失、回执或底层输出现场 SHA-256 不匹配；
- 原问题与被验证陈述缺少独立且 `accept` 的 `statement_faithfulness` 证据；
- 解库所依赖的证据已被后续账本记录失效；
- proof 只经过数值、符号或可重复计算验证；
- counterexample 没有可检查反例证据；
- `solutions.json` 含有无法由当前 Result 派生的 ID；或把 Project/Workflow/Task/Step/Job 的完成状态、退出码或执行回执当作 Result 的数学准入证据。

## 原因

数学研究中最严重的系统性错误，是把尝试、有限样本、局部结果、漂亮证明草稿或较弱形式化陈述误称为完整解。这会污染解库，使后续 Agent 把错误结论当作事实继续推理。

## 检查方式

- Script：`python3 scripts/validate_research_spaces.py`。
- Negative regression：`python3 scripts/test_research_spaces.py`。
- Attack matrix：`python3 scripts/test_evidence_attacks.py`。
- CI：`make check`。
- Manual：审查 Problem statement、Result claim、证明对象与形式化陈述是否一致；机器校验不替代该数学判断。

## 可操作错误提示

当前 Result 的 outcome 与有效 evidence 不满足解库验收谓词。请修正 outcome，补独立直接验证和陈述忠实性证据，或把结果保留为 supported/inconclusive；然后重算解库索引。

## 最小修复

- 把有限证据或局部结果的 outcome 改为 `supported` 或 `inconclusive`；或
- 补齐真实 proof/counterexample 证据与独立验证；或
- 修正被验证陈述，使其忠实于 canonical Problem；或
- 从 `solutions.json` 删除无法由 Result 派生的条目并重新生成索引。
