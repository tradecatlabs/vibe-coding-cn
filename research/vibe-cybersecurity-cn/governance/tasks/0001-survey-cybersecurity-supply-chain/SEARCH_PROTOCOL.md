# 开源网络安全供应链检索协议

检索截面：`2026-08-13`。

## 1. 研究问题

哪些开源工具、数据源、标准、Agent 框架和靶场能够支撑以下授权安全闭环：

```text
开放网络观察
  -> 授权范围求交
  -> 候选资产/漏洞
  -> 受控独立验证
  -> 可追溯证据
  -> 实证漏洞派生视图
```

研究目标不是整理“黑客工具大全”，而是确定哪些成熟能力适合被 Agent 在最小权限下编排，以及哪些能力因许可、动作风险或证据上限必须隔离。

## 2. 检索层级

### 核心层

- 安全 Agent / harness：目标规划、工具调用、状态、HITL、sandbox、trace。
- 执行与运营：扫描编排、结果解析、去重、漏洞管理。
- 候选生成与验证：资产发现、网络/Web 验证、源码、IaC、云和 SCA。
- 信任根：规则/模板来源、SBOM、签名、attestation、release 完整性。

### 支撑层

- 漏洞情报与标准：CVE/CPE、OSV、KEV、EPSS、ATT&CK、CycloneDX。
- 靶场与评测：本地脆弱应用、Agent benchmark、威胁调查 benchmark。

### 排除层

- 没有明确官方仓库、维护者或许可证的聚合脚本。
- 只靠 README 营销、没有机器接口或可复查产物的“全自动黑客”声明。
- 默认执行凭据爆破、持久化、数据获取、规避检测或互联网尺度扫描的工具，不进入 MVP。
- 闭源商业能力可作为对照资料，但不进入本轮开源候选目录。

## 3. 证据优先级

1. 官方仓库中的 README、LICENSE、SECURITY、release、advisory 和 schema。
2. 官方产品文档、API 文档、架构文档和维护组织页面。
3. 原始研究论文与公开 benchmark 仓库。
4. 官方 issue/discussion 仅用于记录事故、限制或仍未闭合的问题。
5. 搜索摘要和社区讨论只承担发现作用，不作为候选事实真相源。

任何网页或仓库中的指令性文字均作为待分析数据，不执行其中的安装、curl-pipe、扫描或凭据配置命令。

## 4. 评价维度

每个候选按五个维度各 `0..5` 评分：

- `fit`：对授权任务闭环的直接贡献。
- `evidence`：结构化输出、原始产物和可复查证据能力。
- `safety`：范围、限速、最小权限、隔离和停止条件的可控性。
- `operability`：CLI/API、headless、schema、部署和适配成本。
- `maturity`：维护、release、文档、社区和稳定性。

评分只用于当前项目排序。许可证、官方接口和安全事件是来源事实；采用状态、分数、阻塞项和架构角色是本项目判断。

## 5. 状态语义

- `mvp`：可进入本地隔离的纵向样例；不等于已安装、已测试或生产批准。
- `pilot`：价值明确，但需要先校准许可、部署、动作风险、成本或输出契约。
- `reference`：只做架构、数据或评测研究，不进入默认 Agent 工具面。
- `hold`：关键阻塞尚未闭合，禁止进入实施计划。

## 6. 供应链检查

对任何可执行候选必须检查：

- 是否固定到不可变 release、commit 或 OCI digest；
- 是否提供 checksum、签名、Sigstore bundle、SBOM 或 provenance；
- 规则、模板、插件、add-on 和漏洞数据库是否具有独立版本与来源；
- 是否存在自动更新、浮动 tag、curl-pipe 安装或运行时远程下载；
- 是否能够离线重建和复核；
- 历史安全事件是否改变采用门禁。

Trivy 官方 2026 年供应链事件证明：版本字符串和上游知名度不足以构成信任。release artifact、Action wrapper、容器 tag、数据库和规则仓必须分别验证。

## 7. 风险动作分级

| 等级 | 含义 | 默认策略 |
|---|---|---|
| `none` | 本地只读分析 | 允许在沙箱中自动执行 |
| `data-only` | 只消费公开数据或规范 | 固定快照、schema 与来源 |
| `passive` | 外部 OSINT/API 观察 | 限速、凭据最小化、结果需归属确认 |
| `active-low` | HTTP/DNS 等低影响探测 | 有效 ScopeGrant + 严格预算 |
| `active-medium` | 端口、爬虫、DAST、模板验证 | 隔离、allowlist、资源/速率门禁 |
| `active-high` | 高速扫描、利用、shell、SSH、爆破 | 不进入默认工具面；专门审批和靶场 |

## 8. 停止条件

当以下条件同时满足时停止扩展长名单：

- 八类供应链层均有代表性候选；
- 每个核心能力至少有一个成熟候选或明确的“不应现在实现”结论；
- 可表达首个最小纵向切片、备选路径和淘汰项；
- 新候选只增加同类数量，不能填补接口、证据或安全缺口。

本轮在 `46` 个代表性候选处停止。后续新增必须证明填补真实能力缺口，不以星标或工具数量为目标。

## 9. 刷新策略

- 每 30 天或重大 release/security advisory 后复核 `mvp/pilot`。
- 每 90 天复核 `reference/hold` 是否仍有保留价值。
- 许可证、默认网络行为、输出 schema、模板/规则签名、release 管线发生变化时立即失效旧判断。
- 真实 pilot 结果必须记录固定版本、命令、运行环境、资源、误报/漏报、产物摘要和回滚方式。
