## 预备知识

本块只介绍后文会用到的范畴论词汇。先记住：对象是正在处理的东西，态射是有方向的变化，复合是步骤连接，交换图是路径一致，对偶是反向观察。

范畴论只负责描述对象之间的关系与变化；实际结果仍由模型、运行时、工具、权限、测试和人的验收共同确认。

### 范畴论的六个基本概念

| 概念 | 直白理解 | 在 Vibe Coding 中的对应 |
|:---|:---|:---|
| 对象 | 正在处理的东西 | 输入、意图、状态、代码、文档、结果、证据 |
| 态射 | 从一个东西到另一个东西的有向变化 | 理解、生成、执行、适配、审查、验证 |
| 复合 | 把多个变化按顺序连接 | 计划、工作流、工程闭环 |
| 恒等态射 | 对象到自身的无变化映射 | 保持输入、约束和结构不变 |
| 交换图 | 同一输入沿不同路径处理，结果仍符合同一约定 | 需求、代码、测试和交付结果保持一致 |
| 对偶 | 把方向反过来重新观察 | 从结果回推条件，从失败追溯原因 |

#### 一、对象

输入、目标、约束、状态、输出、代码、文档、工具、权限、结果和证据都可以作为对象。对象回答：**当前正在处理什么？**

#### 二、态射

理解、描述、拆解、生成、执行、适配、审查和验证都可以作为态射。每个态射都要写清起点、终点和变化内容：

```text
输入对象 ──态射──→ 输出对象
```

态射回答：**发生了什么变化？输入是什么？输出是什么？**

#### 三、复合

如果 `f: A → B`，`g: B → C`，先执行 `f` 再执行 `g`，就可以复合为 `g ∘ f: A → C`。这就是把多个步骤接成一条可执行路径：

```text
输入 → 理解 → 计划 → 执行 → 结果 → 验证
```

复合必须满足结合律。工程上，这意味着先组合前两步还是先组合后两步，不应改变整条路径的规定结果。

#### 四、恒等态射

恒等态射 `id_A: A → A` 表示从对象 `A` 指向它自身且结构不变，并满足：

```text
id_B ∘ f = f = f ∘ id_A
```

工程上，它提醒我们区分“传递已有信息”和“悄悄改变输入、约束或结果含义”。

#### 五、交换图

交换图要求：从同一输入到同一目标存在多条路径时，各路径的复合结果符合同一约定。可以用下面的形式表示：

```text
A ──f──→ B
│        │
h        g
│        │
↓        ↓
C ──k──→ D
```

当 `g ∘ f` 与 `k ∘ h` 按验收标准得到同一结果时，图交换。需求、代码、类型、schema、测试、CI 和检查清单，都是把这个一致性要求固定下来的工程手段。

#### 六、对偶

范畴论中的对偶，是把所有态射方向反转，得到对应的对偶范畴。本项目借此组织反向工作：从目标回推条件，从输出追溯输入，从失败结果定位失效态射，从验收标准反推执行路径。

## Vibe Coding 的五个基础认识

### 1. 先解决人工智能问题

> **Demis Hassabis：“首先解决人工智能问题，然后再用人工智能解决其他所有问题”**

这条原则要求先把 AI 协作链跑通：人明确目标和约束，模型提出候选方案，Harness 调用工具执行，测试和人工验收确认结果。协作链稳定后，再把 AI 用于编程、写作、分析、研究和自动化。

### 2. 生成域

大语言模型直接生成符号对象。给定词表、上下文和工具协议后，模型能够表达的对象与调用路径构成其生成域。这里的生成域只描述模型能写出的内容，不包含执行权限。模型能写出代码或命令，只说明候选描述已经生成；语法、语义、环境和实际结果仍需单独验证。

> **可生成表示候选路径存在，可执行和有效需要额外证据。**

### 3. 模型吞噬

Prompt 技巧、工作流、Agent 编排、索引、外部记忆、脚手架、工具封装和人工流程，都可以看作连接输入与结果的中间态射。“吞噬”指模型能力增强后，原本由这些中间层承担的部分工作可能被模型直接处理；外部边界、权限控制和独立验证仍应保留。

### 4. 隔离审查

生成结果是候选对象，审查是独立的验证态射。重要结果生成后，应开启新的审查会话，不沿用生成会话的结论，重新读取原始目标、约束、代码、文档和验证结果，再判断候选对象是否满足要求：

```text
原始目标 ──生成复合──→ 候选结果
    │                    │
    └──独立验证复合──────→ 证据与结论
```

### 5. 能力编排

遇到需求时，先寻找成熟工具、库、平台和仓库提供的已有能力，把它们当作可复用的现成态射。拼好码负责连接、适配、编排和表达业务规则；只有关键约束无法满足时，才新增核心态射，并限定它的职责。

```text
需求对象 → 能力识别 → 成熟态射组合 → 适配边界 → 业务结果 → 验证证据
```

> **能复用时复合已有能力，能适配时保持边界，必须自研时限定新增职责。**

## 总体运行模型

Vibe Coding 是把一个问题逐步变成已验证结果，并根据反馈继续修正的复合路径：

```text
现实问题 X
  ↓ 识别、描述、约束
目标结构 S
  ↓ Model：理解、推理、生成
候选方案 C
  ↓ Harness：上下文、工具、权限、执行循环
结果状态 S'
  ↓ 观察、测试、审查、记录
证据 E
  ↺ 反馈：修正目标、约束、计划与行动
```

把每一步写成态射：

```text
X ──I──→ S ──M──→ C ──T──→ S' ──V──→ E
```

- `X`：现实中的问题或原始输入。
- `I`：识别、描述和形式化输入的态射。
- `S`：目标、对象、约束和计划组成的结构。
- `M`：Model 生成候选方案的态射。
- `C`：待执行的候选方案。
- `T`：由 Harness、工具和权限组成的执行态射复合。
- `S'`：执行后的系统状态。
- `V`：测试、审查和质量门禁组成的验证态射。
- `E`：可追溯的验证证据。

Model 负责生成符号和行动意图；Harness 负责把候选意图接入工具、权限和执行循环；证据负责说明结果是否成立。可以把它们记成一句话：Model 提出方案，Harness 执行方案，验证证据确认结果。

## 顶层认识

1. **先识别对象。** 明确输入、目标、状态、结果、证据和边界。
2. **再确定态射。** 写清每个动作的输入、输出、前置条件、后置条件和失败路径。
3. **用复合组织任务。** 把理解、计划、执行、验证和反馈连接成可重复的路径。
4. **用交换图检查一致性。** 让需求、代码、测试、文档、配置和交付结果保持对应关系。
5. **用对偶反向审查。** 从结果回到条件，从失败回到失效环节，从验收标准回到执行步骤。
6. **把 Agent 看成复合系统。** Model 生成候选，Harness 管理上下文、工具、权限、记忆和执行循环。
7. **把人的职责放在方向上。** 人确定目标、价值、约束、取舍和最终判断；AI 扩大理解、规划、生成和执行能力；机器门禁把可检查的要求写成测试、脚本和 CI。
8. **把可靠性落到证据上。** 测试、类型、schema、脚本、CI、检查清单和可审查 diff 共同证明路径是否成立。

在本项目中，范畴论把离散的经验、工具和流程统一翻译成对象与态射，让同一件事既能沿正向路径构造，也能沿反向路径审查。遇到新概念时，先问“它是什么对象、连接了什么对象、这条态射如何验证”。

## 总结与完整仓库入口

Vibe Coding 的核心路径可以压缩为：

```text
对象 → 态射 → 复合 → 交换图 → 对偶审查 → 证据
```

本分支把范畴论作为根结构：对象承载问题与结果，态射表达变化，复合组织行动，恒等保持结构，交换图检查一致，对偶支持反向推理。

范畴论负责描述关系和一致性；运行环境、工具、权限、测试和人工验收负责确认结果。两者共同构成可执行、可检查、可回溯的 Vibe Coding 闭环。

极简分支只保留这套根理论及其统一解释。需要完整教程、实践方法、工具配置、Skill、工作流和研究资料时，进入[完整仓库的 develop 分支](https://github.com/tradecatlabs/vibe-coding-cn/tree/develop)。
