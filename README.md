## 范畴论根框架

本分支只保留一套底层语言：范畴论。任何 Vibe Coding 内容先映射为对象、态射和复合，再用交换图检查路径一致性，用对偶从结果反向追溯条件。

### 一、对象

输入、意图、状态、输出、代码、文档、工具、权限、结果和证据都可以作为对象。对象表示系统中需要被识别、转换、保存或验证的东西。

### 二、态射

理解、描述、拆解、生成、执行、适配、审查和验证都可以作为态射。态射表示一个对象如何有边界地转化为另一个对象。

### 三、复合

多步操作由态射复合组成。计划、工作流和工程闭环都可以写成：

```text
输入 → 理解 → 计划 → 执行 → 结果 → 验证
```

复合的意义是让每一步的输出成为下一步的输入，并使整条路径可以重复、检查和替换。

### 四、恒等

保持对象及其结构不变的操作由恒等态射表示。它用于说明某一步只传递已有信息，没有偷偷改变输入、约束或结果含义。

### 五、交换图

当两条不同路径从同一对象出发，最终得到等价对象或等价结果时，图交换。契约、测试、类型、schema、CI 和检查清单，都是把这种一致性要求固定下来的工程手段。

### 六、对偶

对偶把观察方向反转：从目标回推条件，从输出追溯输入，从失败结果定位失效态射，从验收标准反推执行路径。正向构造和反向审查由同一套关系连接。

### 七、Vibe Coding 的五个基础认识

#### 1. 先解决人工智能问题

> **Demis Hassabis：“首先解决人工智能问题，然后再用人工智能解决其他所有问题”**

在本框架中，这句话对应于先建立一条从人的意图对象通向可执行对象的可靠态射。模型生成候选态射，运行时负责工具、上下文、权限、执行和反馈的复合，人负责目标、约束、取舍和最终验收。

#### 2. 生成域

大语言模型直接生成符号对象。模型的能力边界，可以描述为它能够表达哪些对象和态射；能够生成文本，只说明存在可表达的候选路径，仍需经过语法、语义、环境、权限和结果验证。

> **可生成只表示候选路径存在，可执行和有效需要额外态射证明。**

#### 3. 模型吞噬

Prompt 技巧、工作流、Agent 编排、索引、外部记忆、脚手架、工具封装和人工流程，都可以看作连接输入与结果的中间态射。模型能力提升后，可复合、可吸收的中间层会被压缩或替代；长期稳定的结构应保留真实边界，只保留仍然承担独立职责的态射。

#### 4. 隔离审查

生成结果属于候选对象，审查属于独立的验证态射。生成路径和审查路径应尽量隔离，审查者重新读取原始目标、约束、代码、文档和验证结果，再判断候选对象是否与要求交换。

```text
原始目标 ──生成复合──→ 候选结果
    │                    │
    └──独立验证复合──────→ 证据与结论
```

#### 5. 能力编排

成熟工具、库、平台和仓库可以看作已有态射。拼好码只补充连接、适配、编排和业务规则，优先复合已有能力，只有在关键边界无法满足时才新增核心态射。

```text
需求对象 → 能力识别 → 成熟态射组合 → 适配边界 → 业务结果 → 验证证据
```

> **能复用时复合已有态射，能适配时保持边界，必须自研时限定新增态射的职责。**

## 总体运行模型

Vibe Coding 是一条从意图到现实、再从现实回到意图的复合路径：

```text
现实问题对象
  ↓ 描述与约束
意图对象
  ↓ 语言化态射
可处理的描述对象
  ↓ Model：理解、推理、生成
候选方案对象
  ↓ Harness：上下文、工具、权限、执行循环
现实结果对象
  ↓ 观察、测试、审查、记录
证据对象
  ↺ 反馈态射：修正意图、描述、计划与行动
```

可以用一个抽象式表示：

```text
X ──I──→ S ──T──→ S' ──O──→ Y ──V──→ E
```

- `X`：输入或现实中的问题。
- `I`：理解和形式化输入的态射。
- `S`：目标、对象、约束和计划组成的中间结构。
- `T`：由工具、模型和运行时组成的执行态射复合。
- `S'`：执行后的系统状态。
- `O`：把状态转换为交付结果的态射。
- `Y`：代码、文档、配置或其他业务结果。
- `V`：测试、审查和质量门禁组成的验证态射。
- `E`：可追溯证据。

模型负责生成符号和行动意图；Harness 负责把候选意图接入工具、权限和执行循环。结果能否成立，要由现实变化和可追溯证据确认。

## 顶层认识

1. **先识别对象。** 明确输入、目标、状态、结果、证据和边界。
2. **再确定态射。** 说明每个动作的输入、输出、前置条件、后置条件和失败路径。
3. **用复合组织复杂任务。** 把理解、计划、执行、验证和反馈连接成可重复的路径。
4. **用交换图检查一致性。** 让需求、代码、测试、文档、配置和交付结果在关键路径上保持对应关系。
5. **用对偶反向审查。** 从结果回到条件，从失败回到失效环节，从验收标准回到执行步骤。
6. **把 Agent 看成复合系统。** Model 生成候选态射，Harness 管理上下文、工具、权限、记忆和执行循环。
7. **把人的职责放在选择上。** 人确定目标、价值、约束、取舍和最终判断；AI 扩大理解、规划、生成和执行能力；机器门禁固定可验证的关系。
8. **把可靠性落到证据上。** 测试、类型、schema、脚本、CI、检查清单和可审查 diff 共同证明路径是否成立。

范畴论在这里承担统一描述职责：它把离散的经验、工具和流程翻译成可组合的对象与态射，让系统可以沿正向路径构造，也可以沿反向路径审查。

## 总结与完整仓库入口

Vibe Coding 的核心路径可以压缩为：

```text
对象 → 态射 → 复合 → 交换图 → 对偶审查 → 证据
```

范畴论提供顶层结构：对象承载问题与结果，态射表达变化，复合组织行动，恒等保持边界，交换图检查一致，对偶支持反向推理。

极简分支只保留这套根理论及其对 Vibe Coding 的统一解释。需要完整教程、实践方法、工具配置、Skill、工作流和研究资料时，进入[完整仓库的 develop 分支](https://github.com/tradecatlabs/vibe-coding-cn/tree/develop)。
