<a id="philosophy-methodology-toolbox-candidate-minimal-argument"></a>
## 候选：最小论证结构

**用途**：检查一项判断是否有支撑，而不把结论、证据和推理过程混为一谈。

**落地动作**：

1. 写出待判断的结论。
2. 列出支撑结论的依据，并标明依据是观察、数据、规则还是假设。
3. 写出“依据如何推出结论”的连接规则。
4. 补充适用条件、限制和可能推翻结论的反例。

**产物**：结论、依据、连接规则、条件与反例清单。

**边界**：结构完整不等于依据真实，也不保证推理规则正确；需要分别核对来源、逻辑和适用范围。

<a id="philosophy-methodology-toolbox-candidate-library-api-capability-ladder"></a>
## 候选：库、包与 API 能力阶梯

**用途**：规划从调用现成组件到能安全组合、排错和维护组件的学习与工程能力。

1. **调用**：按接口使用组件，理解输入、输出和错误。
2. **选择**：按需求、许可证、维护状态、兼容范围和运行约束比较方案。
3. **组合**：处理接口契约、依赖关系、配置和版本边界。
4. **调试与测量**：定位失败原因及性能瓶颈，区分组件问题与集成问题。
5. **修改或适配**：在可维护边界内封装、替换或扩展组件。
6. **设计或构建**：仅在成熟方案不满足关键约束时，才承担自建和长期维护成本。

**检查问题**：接口承诺是什么？调用前提是什么？失败如何表达？依赖如何锁定？许可证和维护状态是否可接受？升级与回滚如何处理？

**边界**：阶梯表示能力范围，不是功法品级或个人评价；高级别不天然优于复用成熟组件。

<a id="philosophy-methodology-toolbox-candidate-minimal-model-transfer-boundaries"></a>
## 候选：最小模型—迁移—边界回填

**用途**：为复杂问题建立足够简单的模型，并谨慎借用相似结构提出待验证方案。

**落地动作**：

1. 明确目标、对象、关键变量及已知约束。
2. 暂时删去与当前问题无关的细节，保留关键关系，得到最小模型。
3. 搜索结构相似的案例或模型，逐项写明对应关系，不只比较名称或外观。
4. 列出类比不成立的条件，以及简化时暂时忽略的变量。
5. 把现实中的限制、失败模式和边界条件加回模型，用反例或低成本实验检查。

**产物**：最小模型、对应关系、遗漏变量、迁移边界和验证项。

**边界**：模型简化和类比只能生成假设，不证明两域机制相同；无法说明映射关系时不迁移结论。
