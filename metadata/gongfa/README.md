## 项目内总表与维护

只维护一张总表，不再拼接各批次人类分表；Markdown便于Git浏览，Excel包含完整限定原文/源条目、选区、用途、边界、理由和反证。
总表每次读取当前登记，另消费此前已分类候选的仓内快照；不依赖原HTML目录、个人Excel、完整Solve或临时工作目录。
聚合记录数量以[自动生成摘要](catalog.md#字多不看)为准，不能当成已登记数或经语义去重的独立功法数。

```bash
make sync-gongfa-catalog
make check-gongfa-catalog
make test-gongfa-catalog
```

- 登记内容/意见更新仍写`registry.json`，再生成总表；现有协议和正式评级门槛不变。
- 来源候选的旧意见只是来源事实：此前四HTML、Solve仅已审首24和HTML续提。未审材料不混入。
- 候选变更另建冻结快照、更新`catalog-sources.json`的路径/SHA/范围；不要直接修改旧快照或表格。
- 生成脚本复用现有登记校验与[openpyxl](https://openpyxl.readthedocs.io/)，依赖最低/固定版本3.1.2。
- 默认只检查；`--write`只更新带生成标记的视图，不改原文或源意见，拒绝截断文字、公式解释、覆盖非生成文件和越界路径。
- 同名内容保留关联，不自动合并身份；新内容版本不继承旧品级，多情境活动意见不按最高档或最新时间裁决。
- E001灾备模型、VC029 CAP简述仍暂不可判；已知正确性/前提问题不以最低档遮盖，修订须另存限定内容与来源版本。
- 原著、许可证、独立语义批准和效果尚未核验；此次仅本地维护，没有提交、推送或发布授权。

本页后续的来源、续收和两批初评说明记录既有入库轮次，不代替总表的全部来源范围。

## 数据结构

| 区域 | 内容 | 版本与边界 |
|---|---|---|
| `schema_version` | JSON协议版本，当前`1.1.0` | 新增人工初评，不代表评级规约已校准 |
| `vocabulary` | 四阶十二级的稳定值与数组顺序 | `gongfa-grade-vocabulary-v1`；名称、顺序不代表倍率 |
| `policies` | 版本化判级规约 | 当前`gongfa-grading-policy@0.1.0`，状态`draft` |
| `sources` | 原路径/URL、来源修订、原始快照、摘要、明确收录范围 | 网页无Git提交，不伪造；仓内来源固定到提交 |
| `gongfa` | ID、内容版本、限定原文、摘要、来源选择器和人工判定主类指针 | 完整身份是`id@content_version`；同ID可以保留多版 |
| `grade_proposals` | 人工初评批次、内容摘要、分类/评级理由、任务族、置信标签与反证 | 显式批次保存暂定建议及历史；不当成实验结果，不写入正式评级 |
| `assessments` | 对象版本、规约版本、条件、证据、评定者、时间与纠正历史 | 当前为空，尚无正式效果评级；不内嵌永久等级 |

`ontology_type`保留原六条主类，并按限定内容为其余条目明确主类；未来尚未分析的候选可为`null`。
本协议只接受三条基础内容类及复合内容的`dao-content`指针，不接受软件类、等级或新造类；未来细类引用需显式扩展协议。
`entry_status=registered`表示已完成条目登记，不表示已验证效果、完成评级或独立语义审查。

### 内容与摘要

- `original_text`＋`text_sha256`：按来源选择器提取的限定原文，而非整篇文章。
- `profile.provenance=editorial_summary`：编者摘要/原句选择，说明问题、机制、适用条件、边界、预期结果及核心问题。
- `claim_status=source_statement`：记录来源如此表述，不把其主张当成独立实验证明。
- `missing_fields`：未提供的语义字段。空数组表示此条没有提取到说明，不表示没有条件或风险。
- 纯解释内容可以没有步骤或产物；原文中的工具建议不成为唯一依赖或账号授权。

## 分类与人工初评

既有两批入库主类：解释型5、准则型20、方法型45、复合型9。复合型引用既有`dao-content`，不是另造第四条父树。
解释型讲关系，准则型规定取舍，方法型规定怎么做；完整内容同时承担多种功能时保留复合主类。
例如胶水原则是准则型，网页拼好码是复合型，不能凭相似名称合并。

初评分批追加，原批次及意见不覆盖：

| 批次 | 内容范围 | 初评性质 |
|---|---|---|
| `gongfa-author-initial-20261007` | 原58条仓内与页面内容 | 人工初评，完整保持 |
| `gongfa-author-repo-expansion-20261007` | 本轮21条仓内续收内容 | 新增独立意见，不纠正或取代旧范围 |

两批均引用现有规约`0.1.0`的方向作前瞻判断：
黄阶预计限定任务达标，玄阶预计相对合理基线有增益，地阶预计困难/迁移任务仍有用，天阶须预计能突破明确能力缺口。
初/中/高是本阶预计结果带，不是置信度、验证次数或等距倍率；仍待校准，不作跨任务总排名。
没有为了填满词表而判天阶，也没有把缺测自动补成黄阶。

每条初评记录绑定`id@content_version`和限定内容摘要，保存`task_family`、`classification_reason`、`reason`、`confidence`与`falsifier`。
这些是编者判断，不改写原文或`profile`，不宣称已有增益、收敛、胜率或独立评审。
`confidence`只是主观把握标签，不是准确率；`falsifier`是可推翻建议的条件，不是已经执行的失败记录。
共同应用前提、合理基线假设、作者与时间存于批次；基线已采用同一方法时不能预定额外收益。

更正初评追加批次并设置`supersedes`；同一纠正链须保留对象集合、应用情境与基线假设，且无环/无分叉。
不同对象集合或任务范围独立保存；多批次输出表格必须显式选批次，不能把最新时间当全局权威。
输出携带批次ID；“本批未初评”只表示所选批次没有该对象意见，不表示其他批次也未评。
内容新版本不自动继承初评；真正取得受控效果证据后，正式评级另记`assessments`。

## 规则与评级

当前方向仍是提案：黄阶限定任务达标；玄阶对固定基线稳定增益；地阶在困难/迁移任务中达标；天阶突破事先记录的基线能力缺口。
每阶初/中/高对应预先校准的结果带，不能以验证次数、篇幅、复杂度、名气或宏观层次替代结果。
这里的不同任务集必须先固定；不构成跨任务、跨类型的永久总分。

`evaluation_contract=null`且`unresolved`非空，因此当前不能登记`rated`。
未来定稿须固定任务集、基线、环境/预算/应用方式、判级准则工件，均以仓内路径＋SHA-256引用；这比自由文本条件可重复核验。
评级`scope`须与该规约合同对应，效果证据另存于`evidence_refs`，不能仅引用介绍页或把文件存在当成效果成立。

- `unrated`：尚未评定，`grade_id=null`；可不额外创建一条空评级记录。
- `undetermined`：尝试过但不能判定，`grade_id=null`，保留原因及取得的证据。
- `rated`：等级是12值之一，须有已定稿规约、固定条件和至少一个可核验的证据工件。

更正追加记录并设置`supersedes`；同一纠正链必须针对同内容版本、同适用范围且无环/无分叉。
不同任务或条件应有独立结论，不以最新时间自动裁决全局等级；新内容版本不继承旧评级。
`defined`是数据中的规约声明，不是机器替人批准标准，也不证明所引用工件具有有效业务语义。

## 运行与验证

功法检查单独需要Python3.10+，其余脚本的最低版本不变；安装命令在已有Python虚拟环境中运行。
依赖固定版本见[requirements-gongfa.txt](../../scripts/requirements-gongfa.txt)。

```bash
python3 -m pip install -r scripts/requirements-gongfa.txt
make check-gongfa
make test-gongfa
python3 scripts/check-gongfa.py --render-grades
# 当前已有两个批次，必须显式选择内容范围
python3 scripts/check-gongfa.py --render-catalog --proposal-batch gongfa-author-initial-20261007
python3 scripts/check-gongfa.py --render-catalog --proposal-batch gongfa-author-repo-expansion-20261007
```

`--render-catalog`只从JSON输出ID、名称、分类和暂定品级，不改文件、不自动判级；理由在JSON中。
检查汇总的`proposed_grades`是初评记录数（含历史），不是正式评级数。
检查器：Schema、十二级、ID/版本、冻结来源/原文、覆盖、初评/正式评级外键与历史链、条件绑定及证据摘要。
